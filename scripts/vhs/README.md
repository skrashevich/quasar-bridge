# GIF установки в КУЯСЭ

Ролики записаны через [VHS](https://github.com/charmbracelet/vhs) на
[КУЯСЭ](https://github.com/vypivshiy/kuyase): Станция 2, настоящая гостевая
прошивка, root SSH и опубликованный выпуск Quasar Bridge.

| Сценарий | GIF |
| --- | --- |
| Установка через API нейросети | `docs/images/install-api.gif` |
| Повторный запуск установщика с сохранением настроек | `docs/images/update.gif` |

Команды `curl`, `sh`, `ssh`, установщики и Bridge исполняются без подмены.
Архив скачивается с GitHub, контрольные суммы сверяются на компьютере и в госте,
модели и ответ проверки подключения приходят от настоящей нейросети.
Home Assistant пропускается. Ключи API для выбранного локального сервера не нужны.

## Подготовка виртуальной колонки

Нужны Python 3, QEMU AArch64, ADB, OpenSSH, `socat`, подготовленный КУЯСЭ
с образом `work/station2-system.ext4`, ядром и гостевым аппаратным мостом,
а также совместимые статические ARM-бинарники `dropbear` и `dropbearkey`.
Подготовка образов описана в [инструкции КУЯСЭ](../kuyase/README.md).

```sh
python3 scripts/vhs/kuyase-session.py start \
  --emulator-dir /path/to/prepared-kuyase \
  --dropbear-dir /path/to/static-arm-dropbear
python3 scripts/vhs/kuyase-session.py status
```

Помощник копирует образ и запускает отдельную snapshot VM в
`runtime/vhs-kuyase`. ADB используется только для установки SSH-сервера
и временного ключа внутри VM. Запись установщика идёт по настоящему SSH.
Порты хоста привязаны к loopback: SSH `2222`, ADB `25555`, аппаратный мост
`28091`. Помощник отказывается запускаться, если порт занят.
QEMU получает дополнительное правило перенаправления SSH; исходные
бинарники эмулятора и установщика не изменяются.

Поднимите TCP-переадресацию на свой OpenAI-совместимый сервер без API-ключа,
подставив `LLM_HOST` и `LLM_PORT`:

```sh
socat TCP-LISTEN:18080,bind=127.0.0.1,reuseaddr,fork TCP:LLM_HOST:LLM_PORT
```

Это обычная передача байтов без изменения запросов и ответов. Из VM сервер
доступен по `http://10.0.2.2:18080/v1`, где `10.0.2.2` — адрес хоста в сети
QEMU. В записи использована модель `qwen3.8-27b-heretic`; для своего сервера
проверьте номер модели в `install-api.tape`. Не публикуйте ключи или секретные
ссылки в исходниках `.tape`.

## Запись

Нужны `ttyd`, `ffmpeg`, Bash и моноширинный шрифт Menlo с кириллицей
(либо замените `FontFamily` в `common.tape`). Ролики проверены с официальным
бинарником [VHS 0.11.0](https://github.com/charmbracelet/vhs/releases/tag/v0.11.0).
В 0.12.0 обнаружена ошибка: рендер вызывается с отменённым контекстом,
поэтому команда может завершиться без создания GIF.

Из корня репозитория выполняйте сценарии последовательно, в одной VM:

```sh
VHS_BIN=/path/to/vhs-0.11.0
"$VHS_BIN" validate scripts/vhs/*.tape
"$VHS_BIN" scripts/vhs/install-api.tape
"$VHS_BIN" scripts/vhs/update.tape
```

Первый ролик требует чистую VM без Bridge. Повторный запуск `start` после
`stop` создаёт её из исходного образа. Второй ролик использует настройки,
процесс и резервную копию подключения, созданные первым установщиком.
Если новая версия не вышла, повторно устанавливается тот же последний выпуск.

## Границы проверки и остановка

КУЯСЭ работает в штатном режиме `stub`: периферия эмулируется, оригинальный
`maind` не запускается. Проверяются установка файлов, запуск настоящего
Bridge, доступ к нейросети, запись boot hook и изменение конфигурации
подключения. Голосовые ответы физической колонки этим не проверяются.

В мастере выбирается подключение Алисы и откладывается перезагрузка.
Гостевой инициализатор КУЯСЭ запускает `S99*`, а Bridge устанавливает
`S96quasar-bridge`; автоматический запуск после перезагрузки здесь
не проверяется. Установщик и boot hook ради записи не меняются.

После записи остановите VM и отдельно завершите запущенный `socat`:

```sh
python3 scripts/vhs/kuyase-session.py stop
```

Локальные SSH-ключи, образы и логи остаются в игнорируемом `runtime/vhs-kuyase`.
На физические колонки ничего не устанавливается.
