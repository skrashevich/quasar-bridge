# Звук ожидания ответа модели

Чтобы колонка подавала короткий сигнал после выбора маршрута `llm`, включите:

```json
{
  "local_progress": {
    "enabled": true,
    "gpt_cue": true,
    "after_ms": 2000,
    "interval_ms": 4000
  }
}
```

Перезапустите Bridge. По умолчанию `gpt_cue` выключен. Для этого режима требуется
`local_progress.enabled=true`.

Сигнал звучит один раз, в начале существующего потока ожидания. При включённом
флаге этот поток запускается сразу после решения `llm`, без задержки `after_ms`,
в том числе для быстрых ответов. Классификатор ещё может занять время до сигнала.
Для других маршрутов прежнее поведение сохраняется.

Два тона, 660 и 880 Гц, занимают 400 мс вместе с паузами, с пиком около −18 dBFS.
Громкость зависит от настроек колонки. Кадры Opus встроены в бинарник: отдельная
загрузка звука, кодировщик и дополнительные программы на колонке не нужны.
Используются заголовки штатного setup TTS и один Ogg-поток с последующим ответом.
Поддержаны mono/stereo с channel mapping 0; для другой раскладки сигнал пропускается.

Исходный звук создаёт `scripts/generate-thinking-cue.py` с libopus 1.4:

```sh
python3 scripts/generate-thinking-cue.py /path/to/libopus.so.0 internal/bridge/thinking_cue_packets.go
gofmt -w internal/bridge/thinking_cue_packets.go
```

Тесты проверяют быстрые и медленные ответы, единственный сигнал, отмену,
отсутствие сигнала у Yandex, длительность Opus, Ogg CRC/sequence и переход
к финальной речи в том же потоке. Воспроизведение проверено на Станции 2.
