<a id="mcp-oauth"></a>
## OAuth для MCP

Quasar Bridge умеет работать с OAuth по Streamable HTTP. Скопируйте
[пример](../config.mcp-oauth.example.json) в отдельный `config.json` для проверки
или добавьте сервер к своему `assistant_tools.mcp_servers`. Укажите HTTPS-адрес
MCP, точный `issuer` из метаданных провайдера, свой публичный HTTPS URL документа
клиента (`client_id`, CIMD) и только нужные права в `scopes`. Динамическая
регистрация, `client_secret` и OAuth через SSE/stdio не поддерживаются.
Не сочетайте OAuth с `bearer_token_env` или собственным
заголовком `Authorization`.

### Вход через веб-панель

1. В разделе **Аккаунт → Аккаунты MCP** выберите сервер и нажмите **Войти**.
2. Откройте ссылку в новой вкладке и подтвердите доступ у провайдера.
3. Скопируйте из адресной строки **весь** адрес вида
   `http://127.0.0.1:19876/callback?...`. Ошибка открытия страницы ожидаема:
   панель не запускает слушатель для этого адреса.
4. Вставьте адрес в поле **Адрес после входа** и нажмите **Завершить вход**.
   Пока панель ждёт результат, попытку можно отменить. Если ответ потерялся,
   проверьте статус и не вставляйте адрес повторно. Для уже настроенного
   сервера перезапуск Bridge не нужен.

Провайдер должен разрешать указанный адрес возврата. Используйте локальную
панель или SSH-туннель к её порту (по умолчанию `2704`); перенаправлять порт
`19876` для панели не нужно. Не публикуйте панель в интернете и никому не
отправляйте полный адрес возврата: в нём есть одноразовый код. Кнопка
**Выйти…** удаляет только локальные токены. Для автоматического возврата через
локальный слушатель воспользуйтесь [CLI](#mcp-oauth-cli).

<a id="mcp-oauth-cli"></a>
### Вход через CLI

```sh
./quasar-bridge -config config.json -check-config
./quasar-bridge -config config.json -mcp-auth login -mcp-server catalog
./quasar-bridge -config config.json -mcp-auth status -mcp-server catalog
./quasar-bridge -config config.json -check-mcp
```

`login` печатает ссылку. Откройте её в браузере; адрес возврата по умолчанию —
`http://127.0.0.1:19876/callback`. Для другого порта задайте
`-mcp-auth-listen 127.0.0.1:ИЗБРАННЫЙ_ПОРТ`. Адрес возврата должен быть разрешён
вашим провайдером; если он допускает произвольный порт у loopback-адреса,
в документе клиента можно указать `http://127.0.0.1/callback` без порта.

Если бинарник запущен на колонке, подключитесь к ней с компьютера с браузером:

```sh
ssh -L 127.0.0.1:19876:127.0.0.1:19876 user@speaker.example.com
```

Запустите `login` в открытой SSH-сессии, а ссылку — в браузере компьютера.
Не отправляйте URL возврата, код авторизации или токены в чат.

Токены хранятся рядом с используемым конфигом в приватном `.mcp-oauth/` и
обновляются автоматически. Не копируйте этот каталог в общий архив.
`status` и `-check-config` не обращаются к провайдеру; `-check-mcp` подключается
и перечисляет инструменты, но не вызывает их. Если доступ был отозван,
повторите `login`. Команда
`./quasar-bridge -config config.json -mcp-auth logout -mcp-server catalog`
удаляет локальные токены, но не отзывает разрешение у провайдера.

Для комплектного systemd unit с конфигом `/etc/quasar-bridge/config.json`
подготовьте каталог, не открывая весь `/etc/quasar-bridge` на запись:

```sh
sudo install -d -m 0700 -o quasar-bridge -g quasar-bridge /etc/quasar-bridge/.mcp-oauth
```

Выполняйте `-mcp-auth` от имени того же пользователя `quasar-bridge`, который
запускает сервис. Unit разрешает запись только в этот каталог OAuth (помимо
штатного каталога логов). Если используете другой путь к конфигу или симлинк
на другой каталог, добавьте в свой unit разрешение на соответствующий
`.mcp-oauth/` рядом с реальным файлом конфигурации.
