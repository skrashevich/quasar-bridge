# Подробное руководство по Quasar Bridge

[Вернуться к README](../README.md). Здесь собраны полные инструкции по
установке на отдельный сервер и через YAM, настройке и диагностике.

Команды, если не указано иное, выполняются из корня репозитория.

Go-сервер для выборочной обработки запросов Яндекс Станции через нативный
WebSocket-протокол Quasar/Uniproxy:

- умный дом — через Home Assistant, если он подключён, иначе через Яндекс;
- сложные вопросы и распознанные отказы Алисы — через свою LLM;
- музыка, погода, таймеры и другие обычные запросы — через Яндекс.

Распознавание речи (ASR) и озвучивание (TTS) остаются в Яндексе. Даже запрос,
обрабатываемый локально, использует облачный речевой тракт. Схемы протокола:
[freequasar/quasar-go-genproto](https://github.com/freequasar/quasar-go-genproto).

## Что потребуется

- Сервер с Go **1.27.3+**, Git и OpenSSL; Python 3 — для подготовки конфигурации
  колонки и проверки публикуемого дерева. Рабочий сервер можно запустить на отдельном Linux-хосте или на самой колонке через YAM.
- Уже полученный root и SSH-доступ к колонке. Этот проект не получает root
  и не устанавливает изменённую прошивку.
- Доступ сервера к Yandex Uniproxy и API LLM; Home Assistant MCP подключается по желанию.
- Доступ колонки к выбранному TCP-порту Go-сервера. Для DNS-имени сервера
  требуется разрешение этого имени и на колонке, и на машине проверки.
- OpenAI-совместимый API для режима `hybrid`. Совместимый HA MCP нужен только
  для локального управления домом. Режим `observe` работает без обоих API.

Все домены `*.example.invalid` ниже — заменяемые примеры, не готовые endpoints.
`SPEAKER_IP`, `ADMIN_IP`, `SERVER_IP` также нужно заменить своими значениями
в локальной конфигурации. Реальные адреса и секреты в репозиторий не добавляются.

## 1. Получить и собрать проект

```sh
git clone git@github.com:skrashevich/quasar-bridge.git
cd quasar-bridge
go version
go mod download
go build -trimpath -o bin/quasar-bridge ./cmd/quasar-bridge
```

Это сборка для текущей машины. Например, для Linux amd64 с другой машины:

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
  go build -trimpath -o bin/quasar-bridge-linux-amd64 ./cmd/quasar-bridge
```

`-trimpath` убирает локальные пути разработчика из бинарника. Для Linux arm64
используйте `GOARCH=arm64`.

## 2. Проверить сервер в прозрачном режиме

Начните с `observe`: сервер пересылает трафик в Яндекс без локальной маршрутизации.
На этом шаге колонка ещё не перенастраивается.

```sh
umask 077
cp config.observe.example.json config.json
sh scripts/create-cert.sh certs DNS:localhost
./bin/quasar-bridge -config config.json
```

В другом терминале из каталога проекта:

```sh
curl --fail --cacert certs/ca.pem https://localhost:8443/healthz
```

Ожидается JSON со `status: "ok"` и `mode: "observe"`. Это проверка HTTP/TLS
Go-сервера, а не проверка колонки, LLM или HA. Остановите процесс через Ctrl+C
перед дальнейшим редактированием настроек.

Скрипт сертификатов не перезаписывает существующие файлы. Если каталог `certs`
уже существует, используйте его подходящий сертификат либо другой каталог.

## 3. Подключить LLM и Home Assistant

### API LLM

Скопируйте основной пример и откройте локальные файлы настроек:

```sh
cp config.example.json config.json
cp runtime.env.example runtime.env
chmod 600 config.json runtime.env
```

В `config.json` задайте:

- `mode`: `hybrid`;
- `llm_base_url`: базовый URL API **с `/v1`, без `/chat/completions`**;
- `llm_model`: точный идентификатор доступной модели;
- `home_warm_area`: при необходимости имя области HA, например `Кабинет`.

Если API требует ключ, запишите его в `QUASAR_LLM_API_KEY` в `runtime.env`.
Встроенная пара логин/пароль в URL не поддерживается.

Клиент делает `POST /chat/completions` с `stream=false`, `temperature=0`,
`max_tokens=1024` и `chat_template_kwargs.enable_thinking=false`.
Для классификации и планирования действий он также передаёт
`response_format={"type":"json_object"}`. Сервер API должен принимать эти
параметры и возвращать `choices[0].message.content`; одного текстового
completion API недостаточно. Прямой запрос LLM ограничен 60 секундами.

### Home Assistant MCP

Этот раздел необязателен. Для работы только с LLM и Яндексом оставьте
`QUASAR_HOME_MCP_URL` пустым в `runtime.env`:

```sh
QUASAR_HOME_MCP_URL=
```

В `hybrid` по-прежнему задайте `llm_base_url` и `llm_model`. Пустой или
отсутствующий MCP URL отключает интеграцию: HA-клиент и фоновый прогрев не
запускаются, а любой выбор `home` (правило, маршрут по умолчанию или классификатор)
передаётся в Яндекс. Удалять домашние правила из конфига не требуется.
`-route` показывает фактический маршрут `yandex` и `source: "home_disabled"`,
сохраняя имя совпавшего правила; `/healthz` содержит `home_assistant_enabled: false`.
LLM, её инструменты, журнал и контекст диалога продолжают работать.
Подключение или отключение HA требует изменения окружения и перезапуска сервиса.
Непустой MCP URL должен быть корректным HTTP/HTTPS URL: ошибка в нём не отключает
интеграцию молча. Если HA настроен, но недоступен, команда не повторяется в облаке.

Чтобы подключить HA, задайте `QUASAR_HOME_MCP_URL` по инструкции ниже.

Нужен HTTP MCP-сервер с инструментами **`ha_*`**, например
[homeassistant-ai/ha-mcp](https://github.com/homeassistant-ai/ha-mcp).
Установите его по инструкции соответствующей версии проекта и получите
HTTP endpoint с доступом из сети Go-сервера. Для текущего клиента подходит
режим Secret URL / capability URL без интерактивного входа.

Обязательные инструменты:

| Инструмент | Для чего используется |
| --- | --- |
| `ha_get_skill_guide` | Правила работы и `references/device-control.md` |
| `ha_search` | Сущности, состояния, области, псевдонимы и состав групп |
| `ha_get_entity_exposure` | Разрешение сущности для Assist |
| `ha_call_service` | Выполнение команд |
| `ha_get_state` | Независимое чтение состояния после команды |

Клиент посылает MCP JSON-RPC через HTTP POST, принимает JSON и SSE,
передаёт `Mcp-Session-Id`, если сервер его выдал. Он не запускает stdio-сервер
и не выполняет OAuth-вход; отдельный Bearer-заголовок для MCP сейчас не задаётся.
Штатный HA MCP с другим набором инструментов, например только `HassTurnOn`,
не является совместимой заменой этого контракта.

Полный URL, включая секретный путь, задайте в `runtime.env`:

```sh
QUASAR_HOME_MCP_URL='https://home.example.invalid/mcp'
QUASAR_LLM_API_KEY=''
```

Подставьте свой endpoint и ключ; URL из примера не работает. Если URL сам
является секретом, храните его как токен и не публикуйте в выводе диагностики.
Доступ к самому Home Assistant настраивается на стороне HA MCP.

В HA разрешите нужные устройства для **Assist** и проверьте их названия,
области и псевдонимы. Quasar Bridge использует `conversation=true` из
`ha_get_entity_exposure`. Устройство без этого разрешения не попадёт в выборку.
Имя `home_warm_area` лишь подготавливает кеш и **не задаёт комнату по умолчанию**
для команд: комнату лучше называть в запросе.

### Проверка обработчиков без колонки

Загрузите окружение в текущую оболочку и проверьте API:

```sh
set -a
. ./runtime.env
set +a
./bin/quasar-bridge -config config.json -check-backends
./bin/quasar-bridge -config config.json \
  -query 'Спроси нейросеть: объясни, почему небо голубое'
./bin/quasar-bridge -config config.json \
  -query 'Горит ли свет в кабинете?'
```

`-check-backends` запрашивает короткий ответ LLM и, если HA подключён, список его сущностей.
Без HA результат — `LLM: ok; Home Assistant: disabled`; отсутствие интеграции не считается ошибкой.
Он не доказывает возможность физического управления или работу микрофона.
`-query` возвращает JSON с `Route` (`home`, `llm`, `yandex`) и `Answer`.
Команды управления в нём **реально выполняются**. Для `yandex` эта команда
лишь показывает выбранный маршрут: CLI не создаёт сессию колонки, не ставит
таймер и не получает облачный ответ. В режиме `observe` локальные обработчики
на WebSocket не включаются, даже если отдельная проверка `-query` работает.

## 4. Открыть доступ колонки к серверу

Выберите реальное DNS-имя сервера и создайте отдельный сертификат для него:

```sh
BRIDGE_HOST='bridge.example.invalid'  # замените своим DNS-именем
BRIDGE_URL="wss://${BRIDGE_HOST}:8443/uni.ws"
umask 077
mkdir -p private
sh scripts/create-cert.sh private/certs "DNS:${BRIDGE_HOST}"
```

Если в `BRIDGE_HOST` используется IP, вместо `DNS:` передайте `IP:`.
Имя/IP в `BRIDGE_URL` должно совпадать с SAN сертификата. В сертификат
можно передать один SAN; скрипт не добавляет адреса автоматически.

В `config.json` измените следующие поля (остальные параметры `hybrid` сохраните):

```json
{
  "listen": ":8443",
  "tls_cert": "private/certs/server.pem",
  "tls_key": "private/certs/server.key",
  "allowed_ips": ["SPEAKER_IP", "ADMIN_IP", "SERVER_IP"]
}
```

Этот фрагмент — не полный конфиг. Подставьте числовые IP вместо плейсхолдеров.
`listen: ":8443"` слушает сетевые интерфейсы; `allowed_ips` ограничивает
клиентов точными IPv4/IPv6-адресами, **без CIDR и DNS-имён**. Добавьте адреса
машин диагностики, включая сервер при обращении к его сетевому адресу.
Пустой список отключает фильтрацию. Firewall также должен пропускать TCP-порт
от колонки. Для исходящего WebSocket требуется доступ к Yandex Uniproxy.

Убедитесь, что активные `QUASAR_*` из окружения не перекрывают отредактированный
JSON. **В отдельном терминале**, из каталога проекта, загрузите окружение и
оставьте сервер работать в foreground:

```sh
set -a
. ./runtime.env
set +a
./bin/quasar-bridge -config config.json
```

В основном терминале, где заданы `BRIDGE_HOST` и `BRIDGE_URL`, проверьте endpoint:

```sh
curl --fail --cacert private/certs/ca.pem "https://${BRIDGE_HOST}:8443/healthz"
```

При проверке с другой машины скопируйте туда публичный CA и задайте
`BRIDGE_HOST` заново: переменные оболочки не переходят между терминалами.

Сертификат сервера действителен 90 дней, CA — 365 дней. Автоматического
продления нет. При замене CA понадобится обновить доверие на колонке;
приватный `ca.key` на колонку не переносится.

## 5. Направить rooted-колонку на Go-сервер

Ниже — процедура для firmware с конфигурацией
`/system/vendor/quasar/quasar.cfg` и CA bundle
`/system/vendor/quasar/ca-certificates.crt`. До выполнения проверьте пути
и структуру своей firmware. Сценарии применения предполагают возможность
`mount -o remount,rw /`; наличие root само по себе этого не гарантирует.

В основном терминале задайте свой SSH-адрес и порт. Здесь должны сохраняться
`BRIDGE_URL` и `BRIDGE_HOST` из предыдущего шага; сервер продолжает работать
в отдельном терминале:

```sh
SPEAKER_HOST='speaker.example.invalid'  # замените адресом или SSH-алиасом
SPEAKER_SSH_PORT=22                    # замените портом root SSH
STAGE='/data/opt/quasar-bridge-stage'
umask 077
mkdir -p private
ssh -p "$SPEAKER_SSH_PORT" "root@$SPEAKER_HOST" \
  'cat /system/vendor/quasar/quasar.cfg' > private/quasar.cfg.orig
ssh -p "$SPEAKER_SSH_PORT" "root@$SPEAKER_HOST" \
  'cat /system/vendor/quasar/ca-certificates.crt' > private/ca-certificates.crt.orig
```

Сохраните исходники и подготовьте изменённую копию **на своём компьютере**:

```sh
python3 - "$BRIDGE_URL" <<'PY'
import json
import sys
from pathlib import Path

source = Path('private/quasar.cfg.orig')
config = json.loads(source.read_text())
config['aliced']['uniProxyUrl'] = sys.argv[1]
config['aliced']['uniProxyQuicUrl'] = ''
Path('private/quasar.cfg.pilot').write_text(
    json.dumps(config, ensure_ascii=False, indent=2) + '\n'
)
PY
```

Изменяются только адрес голосового WebSocket и отключение QUIC-обхода.
Остальную конфигурацию сохраните: она может содержать данные аккаунта.
Подготовленные файлы находятся в игнорируемом каталоге `private/`.

Перенесите конфигурацию, **публичный** CA и скрипты через SSH. Этот способ
не требует SFTP на embedded-устройстве:

```sh
ssh -p "$SPEAKER_SSH_PORT" "root@$SPEAKER_HOST" "mkdir -p '$STAGE'"
for name in apply-pilot.sh rollback-pilot.sh; do
  ssh -p "$SPEAKER_SSH_PORT" "root@$SPEAKER_HOST" \
    "cat > '$STAGE/$name'" < "scripts/$name"
done
ssh -p "$SPEAKER_SSH_PORT" "root@$SPEAKER_HOST" \
  "cat > '$STAGE/quasar.cfg.pilot'" < private/quasar.cfg.pilot
ssh -p "$SPEAKER_SSH_PORT" "root@$SPEAKER_HOST" \
  "cat > '$STAGE/bridge-ca.pem'" < private/certs/ca.pem
ssh -p "$SPEAKER_SSH_PORT" "root@$SPEAKER_HOST" \
  "sh '$STAGE/apply-pilot.sh' '$STAGE' && reboot"
```

Скрипт сохраняет исходный config и CA на колонке в
`/data/opt/quasar-bridge-backup` и возвращает корневую FS в read-only.
Повторное применение поверх отмеченного пилота отклоняется.

Для нестандартных путей предусмотрены `QUASAR_DEVICE_CONFIG`,
`QUASAR_DEVICE_CA_BUNDLE`, `QUASAR_DEVICE_BACKUP_DIR`. Передавайте одинаковые
значения удалённым скриптам применения и отката; локальный `export` не
переносит их в SSH автоматически. Команды чтения файлов выше тоже нужно
адаптировать к этим путям.

После перезагрузки проверьте три запроса на колонке:

| Запрос | Ожидаемый обработчик |
| --- | --- |
| «Алиса, какая завтра погода?» | Яндекс |
| «Алиса, спроси нейросеть: объясни, почему небо голубое» | Своя LLM |
| «Алиса, горит ли свет в кабинете?» | HA + своя LLM для ответа |

Физическое управление проверяйте на выбранном устройстве и сверяйте его
состояние в HA. Голосовое «готово» или HTTP 200 само по себе не подтверждает
изменение состояния.

## Запуск на самой колонке через YAM

Отдельный хост для Go-прокси не требуется: пакет запускает сервер на rooted
колонке с Linux ARM64. API LLM, необязательного Home Assistant, ASR и TTS остаются сетевыми
сервисами. Проверена Станция 2 с ARM64 и Linux 4.9; другие модели и прошивки
нужно проверять отдельно. Для 32-битных колонок этот пакет не подходит.

### Собрать и установить пакет

Готовый пакет Linux ARM64 и его `.yap.sha256` доступны в
[GitHub Releases](https://github.com/skrashevich/quasar-bridge/releases/latest).
Скачайте оба файла из одной версии и проверьте пакет перед установкой:

```sh
shasum -a 256 -c quasar-bridge-0.3.6-linux-arm64.yap.sha256
```

На компьютере нужны Go из `go.mod` и Python **3.11+**. На самой колонке Go,
Python и libc для этого бинарника не нужны: сборка статическая, `CGO_ENABLED=0`.

```sh
python3 scripts/build-yap.py
# dist/quasar-bridge-0.3.6-linux-arm64.yap
# dist/quasar-bridge-0.3.6-linux-arm64.yap.sha256
```

Это ZIP-пакет `.yap` с `plugin.toml`, бинарником, скриптами службы, `LICENSE`, `NOTICE` и `THIRD_PARTY_NOTICES`. Формат
соответствует [YAM](https://github.com/nyakokitsu/yam/blob/main/docs/PACKAGES.md),
установка проверена на **YAM 0.1.15**. Файл `.sha256` содержит контрольную сумму.
Сборщик использует явный список файлов: локальные конфиги, env, сертификаты и
журналы не включаются. Максимальный распакованный размер — 32 МиБ, лимит YAM.

Установите YAM по его [инструкции](https://github.com/nyakokitsu/yam/blob/main/docs/DEPLOYMENT.md).
Нужны root, работающий доступ к колонке и разрешение `allow_plugin_binaries = true`
в `settings.toml` **демона yamd**. Сохраните остальные параметры этого файла и
перезапустите yamd. Пакету требуется permission `exec`, аппаратные permissions
не используются.

На компьютере, где установлен CLI `yam`:

```sh
export YAM_URL="http://$SPEAKER_IP:8099"
yam install dist/quasar-bridge-0.3.6-linux-arm64.yap
yam service enable quasar-bridge
yam service logs quasar-bridge
```

Если yamd слушает только loopback, используйте SSH-туннель вместо открытия API
в LAN. Замените `SPEAKER_SSH` своим SSH-алиасом с нужными портом и ключом:

```sh
ssh -N -L 18099:127.0.0.1:8099 SPEAKER_SSH
# В другом терминале:
export YAM_URL=http://127.0.0.1:18099
```

Пакет первоначально работает в `observe` на **`127.0.0.1:8443`**, без TLS.
Установка и включение пакета **не меняют конфигурацию речевого тракта**.
Один сервер обслуживает колонку, на которой установлен; listener не открыт в LAN.

### Настроить локальный экземпляр

Команды этого подраздела выполняются **в SSH-shell колонки**. В примерах YAM
установлен в стандартный каталог своего установщика. При другом `--data-dir`
поменяйте `pkg`:

```sh
pkg=/data/quazar/yam/data/plugins/quasar-bridge
state=/data/opt/quasar-bridge
sh "$pkg/control.sh" check
wget -q -O - http://127.0.0.1:8443/healthz
```

При первом старте создаётся `$state/config.json`. Для `hybrid` выставьте в нём
`mode`, `llm_base_url`, `llm_model` и нужный `routing` по разделам выше/ниже.
Сохраните `listen: "127.0.0.1:8443"`, пустые `tls_cert`/`tls_key` и loopback ACL.
Секреты положите в **`$state/runtime.env`**, например:

```sh
QUASAR_HOME_MCP_URL='https://ha.example.invalid/mcp/private-token'
QUASAR_LLM_API_KEY='replace-if-required'
GOMAXPROCS=1
GOMEMLIMIT=64MiB
```

Если HA не нужен, оставьте `QUASAR_HOME_MCP_URL` пустым или не добавляйте эту строку.

`runtime.env` загружается как shell-файл, значения с пробелами/спецсимволами
заключайте в кавычки. Права: каталог `0700`, config и env `0600`.
`SSL_CERT_FILE` по умолчанию указывает на штатный
`/system/vendor/quasar/ca-certificates.crt`, чтобы Go доверял сертификатам
Yandex. Его можно переопределить в env. `GOMEMLIMIT` — мягкая цель GC, не жёсткий
лимит RAM. `home_warm_area` можно оставить пустым, чтобы не делать фоновый прогрев.

Каталог состояния находится **вне пакета**: YAM удаляет и заменяет каталог
пакета при обновлении. Конфиг, env, журнал и резервная копия endpoint сохраняются
при обновлении и удалении пакета. Для нестандартного размещения задайте
`QUASAR_DATA_DIR` в окружении запуска yamd; его нельзя переносить только записью
в `runtime.env`, поскольку файл ищется уже в выбранном каталоге.

После изменений окружения или backend-параметров в SSH-shell колонки:

```sh
sh /data/quazar/yam/data/plugins/quasar-bridge/control.sh restart
```

Скрипт вызывает stop/start через API YAM и ждёт освобождения listener между
ними, затем проверяет healthz. Это устраняет гонку немедленного stop/start в
CLI YAM 0.1.15. Для нестандартного адреса API задайте `QUASAR_YAM_URL`.

Для изменения только `routing` или `conversation_log` найдите PID по `ps` в
SSH-shell и отправьте `kill -HUP PID`; проверьте `routing_reloaded` в логах и
`/healthz`. `control.sh check` проверяет JSON, но не применяет изменения.

### Переключить речевой тракт и настроить загрузку

Убедитесь, что `/healthz` отвечает, backend-проверки работают, а старый путь
подключения сохранён. В SSH-shell колонки:

```sh
pkg=/data/quazar/yam/data/plugins/quasar-bridge
sh "$pkg/control.sh" apply
```

Команда сначала проверяет локальный сервер, затем временно remount'ит `/` в RW,
сохраняет **текущие** `aliced.uniProxyUrl` и `uniProxyQuicUrl` в
`/data/opt/quasar-bridge/endpoint-backup.json`, выставляет
`ws://127.0.0.1:8443/uni.ws`, отключает QUIC-обход и возвращает `/` в RO.
Остальные поля firmware config сохраняются. Если backup уже есть, он не
перезаписывается; при постороннем изменении endpoint операция отклоняется.
Использование plaintext WS допустимо здесь только на loopback; для LAN см. TLS
выше. Поддержка такого endpoint зависит от firmware.

YAM автоматически запускает **включённые** службы после своего запуска.
Сам yamd тоже должен запускаться при загрузке колонки. Если это уже настроено,
второй startup hook не устанавливайте. Для rooted BusyBox-прошивки с
`/etc/init.d/rcS` в пакет включён пример `S98quasar-yam`. Проверьте его пути:
он запускает yamd из `/data/quazar/yam/bin/yamd` на **loopback:8099**. Затем:

```sh
mount -o remount,rw /
cp "$pkg/S98quasar-yam" /etc/init.d/S98quasar-yam
chmod 0755 /etc/init.d/S98quasar-yam
sync
mount -o remount,ro /
```

Не подменяйте уже существующий init-скрипт без проверки. На другой системе
используйте её init-механизм. После установки автозапуска перезагрузите колонку
и проверьте локальный `/healthz`, новые кадры после фразы, ответ и журнал.
Изменение endpoint применяется после перезапуска речевых процессов или колонки.

### Обновление, остановка и откат

Для обновления установите новый `.yap`, затем выполните
`sh /data/quazar/yam/data/plugins/quasar-bridge/control.sh restart` в SSH-shell
колонки. Данные в `$state` не перезаписываются.
Старые пакеты сохраняйте для возврата предыдущего бинарника.

**Перед отключением или удалением** службы верните endpoint, иначе колонка
будет обращаться к остановленному listener. В SSH-shell:

```sh
sh /data/quazar/yam/data/plugins/quasar-bridge/control.sh rollback
# Перезапустите речевые процессы или колонку, затем на компьютере:
# yam service disable quasar-bridge
# yam rm quasar-bridge
```

Rollback восстанавливает только два сохранённых endpoint и не затирает другие
позднейшие изменения firmware config. При несовпадении текущего endpoint
откат останавливается для ручной проверки. Пакет не имеет uninstall hook в YAM:
`yam rm` сам не возвращает настройки firmware. Init hook и каталог состояния
удаляются отдельно, когда больше не нужны; общий yamd с другими пакетами
останавливать или удалять не требуется.


## Журнал запросов и ответов

По умолчанию тексты **не записываются**. Для включения добавьте в `config.json`:

```json
"conversation_log": {
  "enabled": true,
  "path": "runtime/conversations.jsonl",
  "max_size_mb": 10,
  "max_backups": 3,
  "max_text_chars": 16000
}
```

Перечитайте конфиг через `SIGHUP` или `systemctl reload quasar-bridge`.
Это работает и для уже открытых соединений. Для выключения установите
`enabled: false` и перечитайте снова. Изменение параметров журнала и routing
проверяется до применения; ошибка файла/JSON сохраняет предыдущие настройки.
В `/healthz` есть `conversation_log_enabled` и счётчик ошибок записи
`conversation_log_failures`. Ошибка записи не прерывает ответ колонке.

Одна строка JSON — одно событие: `request` (TextInput/VoiceInput/SpeechInput),
`transcript` (финальное ASR), `route`, `cloud_response`, `response` или `cancel`.
В `response` записывается текст, успешно отправленный по WebSocket колонке;
это не подтверждение, что пользователь его услышал. `cloud_response` — ответ,
полученный из Яндекса, в том числе заменённый локальной моделью. Наличие пары
`cloud_response` и `response` с одинаковым текстом ожидаемо: это получение и
доставка одного ответа. Корреляция — поля `session` и хешированный `request`.
`text` содержит карточки, `speech` — текст озвучивания, `route` — выбранный
обработчик (до выбора маршрута в hybrid поле отсутствует), `elapsed_ms` — время от начала запроса. Промежуточное ASR, raw
protobuf/JSON, OAuth/HTTP-заголовки, URL с токенами и аудиофреймы не сохраняются.
Двоичные команды без текстового ответа не превращаются в выдуманный текст.
Диагностический `-query` не является запросом колонки и в этот журнал не попадает.

Файлы создаются с правами `0600`, новые каталоги — `0700`. Путь считается от
рабочего каталога процесса. При достижении лимита журнал становится `.1`, затем
`.2` и т. д.; хранится текущий файл плюс `max_backups` архивов. Длинный текст
обрезается по Unicode-символам с признаком `truncated: true`.
Тексты могут содержать личные данные, даже когда служебные токены исключены.
Журналы исключены из Git и пакета.

Для systemd задайте **`path: "/var/log/quasar-bridge/conversations.jsonl"`**:
обновлённый unit создаёт writable-каталог через `LogsDirectory=quasar-bridge`.
При обновлении старого unit добавьте также `LogsDirectoryMode=0700` и выполните
`systemctl daemon-reload` с перезапуском службы. Для пакета на колонке пример
использует `path: "conversations.jsonl"`, **1 МиБ × 3 файла** с учётом текущего,
чтобы ограничить расход flash. Не ставьте большой журнал на маленькую `/data`.

## Контекст последовательных вопросов

Локальная LLM получает предыдущие вопросы и ответы той же колонки. Например:
«О чём мы сегодня общались?» → «А вчера?» → «А сегодня?». Короткое уточнение
остаётся в локальном диалоге; поиск истории выполняется заново за указанную
в последней реплике дату. Классификатор также получает недавние реплики.

```json
{
  "dialogue_context": {
    "enabled": true,
    "ttl_seconds": 300,
    "max_turns": 6,
    "max_chars": 12000
  }
}
```

По умолчанию включено: до 6 пар «вопрос — ответ», до 12000 символов,
5 минут бездействия. Лимиты допускают 1–20 пар, 512–65536 символов и
30–86400 секунд. Изменение настроек требует перезапуска Go-сервера.
Контекст хранится в оперативной памяти и очищается при перезапуске или
фразе «Алиса, начни новый разговор». Он отделён от постоянного JSONL-журнала.

Ключом служит идентификатор устройства или установки из Quasar; без них
память ограничена одним WebSocket-соединением. При наличии идентификатора
переподключение колонки сохраняет контекст. На одной колонке эта память
общая для говорящих рядом людей; разделения по голосу нет.

Контекст применяется к разговорам с локальной LLM. Явные правила для нового
запроса сохраняют приоритет: музыка, погода и команды умного дома выбирают
свой маршрут и завершают прежнюю локальную тему. Прошлые команды не передаются
в планировщик физических действий. Если в контекст попала личная история,
веб-инструмент остаётся заблокированным до завершения, сброса или истечения контекста.
В памяти сохраняются финальные реплики; сырые результаты инструментов не копируются.

## Долгие локальные ответы и тайм-аут колонки

Некоторые прошивки ждут первоначальный ответ около 15 секунд. Если LLM или
Home Assistant отвечает дольше, включите серверное ожидание:

```json
{
  "local_progress": {
    "enabled": true,
    "after_ms": 2000,
    "interval_ms": 4000
  }
}
```

Добавьте этот блок в основной конфиг и **перезапустите** Go-сервис. В пакете YAM:
`./control.sh restart` из каталога установленного пакета. По умолчанию режим
выключен; `config.example.json` показывает включённый вариант.

После выбора локального маршрута сервер ждёт `after_ms`, затем при необходимости
начинает беззвучное ожидание. Пока обработчик работает, сервер передаёт потоковые
сообщения Quasar и тишину в одном непрерывном Ogg/Opus-потоке. Готовый ответ
добавляется в тот же поток; колонка завершает воспроизведение после его окончания.
Прошивочный тайм-аут менять не требуется. Пауза не ускоряет модель и не снимает
общий лимит обработки запроса.

`after_ms` допускает 100–10000 мс, `interval_ms` — 1000–10000 мс и задаёт частоту
промежуточных сообщений. Отсчёт начинается **после классификации**; длительная
классификация по-прежнему входит в начальные 15 секунд. Для частых запросов
задавайте прямые правила маршрутизации и ограничивайте `classifier.timeout_ms`.
Быстрые локальные ответы и запросы маршрута `yandex` используют прежний тракт.
Переход к LLM после отказа облака не использует этот режим ожидания.

Беззвучный режим проверен на Станции 2 с настоящим ответом после 15 секунд.
Он рассчитан на TTS `audio/opus`; другие кодеки не объединяются. Отмена запроса
останавливает ожидание и передачу тишины. В JSONL-журнале промежуточные сообщения
имеют тип `progress`, поэтому пустые сообщения ожидания не попадают в ответы при поиске истории.

## Инструменты локальной LLM

В обработчике `llm` доступны стандартные OpenAI `tool_calls`. Модель выбирает
функцию, сервер выполняет её и отправляет результат модели для окончательного
голосового ответа. Текущее время подготавливается локально перед генерацией;
для явно указанного HTTP/HTTPS URL заранее читается страница, а для вопроса об истории выбираются восемь последних записей
(для «сегодня» — с начала дня в настроенном часовом поясе). Это убирает лишние
обращения к модели и сокращает ожидание на колонке. Модель может уточнить выборку
через `search_history`, если предварительных данных недостаточно. Классификатор маршрутов и планировщик Home Assistant
продолжают использовать обычные completions без этих инструментов.

| Инструмент | Что делает |
| --- | --- |
| `read_webpage` | Читает публичную HTTP/HTTPS страницу по URL, извлекает текст HTML с учётом кодировки или возвращает plain text / JSON. JavaScript не исполняется |
| `search_history` | Ищет запросы колонки и доставленные ответы в текущем JSONL и его сохранённых архивах |
| `current_time` | Возвращает дату, время, день недели и настроенный часовой пояс |

Примеры фраз: «Прочитай страницу https://example.org и перескажи», «Найди в
истории, что я спрашивал про свет», «Спроси нейросеть, какая сейчас дата и время».
Первое правило по умолчанию `assistant_readonly` направляет маркеры истории и
чтения URL в LLM **раньше** домашнего правила: фраза «найди в истории запрос
включи свет» должна искать запись, а не повторять действие.

Если ваш `routing.rules` уже задан явно, массив автоматически не дополняется.
Перенесите `assistant_readonly` из нового `config.example.json` в начало своего
массива. Явный префикс «спроси нейросеть» по-прежнему работает для обычных
диалоговых вопросов. Встроенный общий веб-поиск по поисковику не включён (его можно добавить через MCP): `read_webpage`
читает конкретный URL, указанный пользователем или выбранный моделью.

### Конфигурация инструментов

В `config.json`:

```json
"assistant_tools": {
  "enabled": true,
  "web": true,
  "history": true,
  "time": true,
  "timezone": "UTC",
  "max_rounds": 3,
  "max_calls": 4,
  "web_timeout_ms": 8000,
  "web_max_bytes": 1048576,
  "web_max_chars": 12000,
  "history_max_scan_mb": 16
}
```

Выберите свой IANA timezone, например `Europe/Paris`. База часовых поясов
включена в бинарник и доступна на колонке без системного zoneinfo.
`enabled: false` отключает tool-calling целиком; отдельные флаги убирают функции
из списка, доступного модели. Если `assistant_tools` отсутствует, инструменты
выключены для совместимости с API без function calling. Готовый hybrid-пример
включает их; observe- и device-примеры оставляют выключенными до настройки.

Изменение `assistant_tools` требует **перезапуска** процесса: для YAM используйте
`control.sh restart`, для systemd — `systemctl restart quasar-bridge`.
`/healthz` показывает `assistant_tools_enabled`. SIGHUP по-прежнему перечитывает
только `routing` и `conversation_log`; смена пути журнала применяется к поиску
истории сразу. У API LLM должна быть поддержка OpenAI-compatible
`tools`, `tool_choice`, сообщений `tool` и `tool_call_id`.

Один ответ ограничен `max_calls` вызовами, запрошенными моделью, и `max_rounds` раундами; затем модели
остаётся финальный ответ по уже полученным данным. Общий timeout — 65 секунд.
Дополнительно выполняется не более двух быстрых локальных вызовов контекста:
время и чтение явно указанного URL либо релевантная предварительная выборка истории. Они не требуют обращения
к API LLM. Инструменты работают последовательно. После успешного `search_history`
новые `read_webpage` в этом же ответе блокируются сервером, в том числе внутри
одной пачки tool calls: содержимое истории нельзя отправить на сайт через URL.
Если нужны оба источника, модель должна сначала прочитать веб, затем историю. Неизвестные/выключенные функции и неверные
аргументы возвращают ошибку; shell и чтение произвольных локальных файлов
модели не предоставляются. Рабочий лог `assistant_tool` содержит имя, результат
успеха и длительность, без аргументов и содержимого истории/страниц.

### История и ограничения веб-чтения

Для накопления истории включите `conversation_log.enabled`. Поиск читает только
файлы из этого настроенного журнала и его `.1`…`.N`, включая записи, оставшиеся
после выключения записи. Функция не восстанавливает уже удалённые архивы.
`query` — слова, которые все должны встретиться в запросе или ответе, без учёта
регистра и различия `е/ё`; пустая строка возвращает последние записи.
`limit` — от 1 до 20, по умолчанию 5; `since` и `until` — необязательные
RFC3339 timestamps, нижняя граница включается, верхняя — нет.

Возвращаются время запроса в настроенном часовом поясе, его текст, доставленный ответ и маршрут. Финальное
ASR объединяется с голосовым запросом; копия `cloud_response` не дублирует ответ.
Текущий незавершённый вопрос исключается; запросы без ответа старше 90 секунд
могут вернуться с пустым ответом. Выдача отсортирована от новых к старым, текст
каждого поля ограничен 1200 символами. История общая для колонок, использующих
один файл журнала; пакет на колонке по умолчанию имеет собственный файл.

`history_max_scan_mb` ограничивает объём чтения, отдавая приоритет новым данным;
при усечении или повреждённых строках результат помечается `partial: true`.
Чтение идёт без блокировки голосового тракта; при одновременной ротации это
best-effort выборка. Содержимое выбранных записей отправляется **вашему API LLM**,
как и сам вопрос, даже если журнал хранится на колонке.

Web reader принимает только публичные HTTP/HTTPS адреса, проверяет DNS и каждое
перенаправление и подключается к проверенному IP. Loopback, частные, link-local
и служебные диапазоны запрещены. Cookies, HTTP-аутентификация и proxy из
окружения не используются. Для маршрута Home Assistant применяется отдельный MCP-клиент, а не
чтение его приватного URL этим инструментом.

Поддерживаются HTML, XHTML, plain text и JSON; объём загрузки, число символов,
redirects и timeout ограничены. Страницы с обязательным JavaScript, логином,
anti-bot защитой или другим типом данных могут быть недоступны. Извлечённые
страницы и старые ответы передаются как данные, а не как системные инструкции.

## Свои MCP-серверы

Диалоговая LLM может использовать инструменты из ваших MCP-серверов, в том числе
без Home Assistant. Поддерживаются **Streamable HTTP**, старый **HTTP+SSE** и
локальные процессы **stdio**. Клиент реализован на официальном
[Go SDK MCP](https://github.com/modelcontextprotocol/go-sdk).

### Пример: поиск через Parallel

Скопируйте [config.mcp.example.json](../config.mcp.example.json), задайте свои `llm_base_url` и `llm_model`,
загрузите `runtime.env` и проверьте подключение:

```sh
cp config.mcp.example.json config.json
set -a
. ./runtime.env
set +a
./bin/quasar-bridge -config config.json -check-config
./bin/quasar-bridge -config config.json -check-mcp
```

В примере включён [Parallel Search MCP](https://docs.parallel.ai/integrations/mcp/search-mcp)
по адресу `https://search.parallel.ai/mcp` с инструментами `web_search` и
`web_fetch`. На момент проверки этот endpoint работает без аккаунта и API-ключа;
у сервиса есть ограничения бесплатного доступа. Подключение к нему не включается
в обычном конфиге автоматически.

Чтобы добавить сервер к существующему конфигу, дополните `assistant_tools`:

```json
{
  "assistant_tools": {
    "enabled": true,
    "mcp_servers": [
      {
        "name": "parallel",
        "transport": "streamable_http",
        "url": "https://search.parallel.ai/mcp",
        "allowed_tools": ["web_search", "web_fetch"],
        "timeout_ms": 20000,
        "max_result_chars": 3000
      }
    ]
  }
}
```

`-check-mcp` выполняет соединение и discovery, показывает имена и количество
доступных инструментов, но **не вызывает их и не обращается к LLM**. При ошибке
сервера возвращает ненулевой exit code. Для проверки полного пути:

```sh
./bin/quasar-bridge -config config.json \
  -query 'Спроси нейросеть: найди в интернете официальную документацию Go по context.WithTimeout'
```

На колонке можно сказать «Алиса, спроси нейросеть: найди официальную документацию
Go по context.WithTimeout». Префикс направляет запрос в локальную LLM. В полном
MCP-примере также добавлено правило для «найди в интернете» и «поищи в интернете».
Для других MCP добавьте свои правила `route: "llm"` или уточните промпт
классификатора. Простое подключение сервера не меняет маршрутизацию музыки,
таймеров и других запросов; правило `home` по-прежнему имеет свою позицию в списке.
Если домашними устройствами должен управлять ваш MCP, поставьте соответствующее
правило `llm` **перед** домашним правилом.

### Авторизация и локальные процессы

Для HTTP/SSE серверов можно задать `url_env` вместо `url`, если адрес содержит
секретный путь, `bearer_token_env` для Bearer-ключа и `headers_env` для других
заголовков. Значения этих полей — **имена переменных окружения**, а не сами секреты:

```json
{
  "name": "private_api",
  "url_env": "CUSTOM_MCP_URL",
  "bearer_token_env": "CUSTOM_MCP_TOKEN",
  "headers_env": {"X-Tenant": "CUSTOM_MCP_TENANT"}
}
```

Переменные задаются в локальном `runtime.env`. Для старого SSE endpoint явно
укажите `"transport": "sse"`. HTTP redirects и переходы SSE на другой origin
не допускаются; указывайте конечный URL. Интерактивные OAuth-входы, sampling и
запросы MCP к пользователю сейчас не поддерживаются.

Для stdio сервер запускается **на том же хосте, где работает Go-прокси**:

```json
{
  "name": "notes",
  "transport": "stdio",
  "command": "python3",
  "args": ["-m", "your_mcp_server"],
  "env": {"MCP_LOG_LEVEL": "warning"},
  "env_from": {"API_KEY": "NOTES_MCP_API_KEY"},
  "allowed_tools": ["list_notes", "create_note"]
}
```

Команда — пример: установите собственный сервер и его runtime самостоятельно.
При запуске Go-прокси на колонке это должны быть доступные на ней программы и
бинарники подходящей архитектуры. Команда вызывается напрямую, без shell;
`args` — отдельные аргументы. `env` содержит обычные значения, `env_from`
переносит выбранные переменные из окружения Go-процесса. Автоматически передаются
только базовые переменные вроде `PATH`, `HOME`, локали и путей CA; ключи LLM и
секреты HA не передаются автоматически. stderr MCP-процесса не
перепечатывается в журнал Go-сервера.

### Выбор инструментов и ограничения

- `name` — уникальное имя сервера: `[a-z][a-z0-9_-]{0,19}`. Модели выдаются имена
  `mcp__ИМЯ__ИНСТРУМЕНТ_ХЕШ`, поэтому одинаковые имена у разных серверов не конфликтуют.
- `allowed_tools` — список исходных имён инструментов MCP; пустой или отсутствующий
  список разрешает все обнаруженные. `denied_tools` исключает инструменты и имеет
  приоритет. `disabled: true` временно отключает сервер.
- Инструменты доступны только обработчику `llm`, в рамках общих `max_rounds` и
  `max_calls`. Они могут менять состояние, если это умеет сервер: подключайте
  доверенные MCP и задавайте нужный список инструментов. Повтор идентичного вызова
  без аннотации `readOnlyHint: true` в одном ответе возвращает сохранённый результат,
  включая ошибку; автоматического повтора после неизвестного исхода нет.
- `timeout_ms` — лимит discovery и каждого вызова (по умолчанию 10000, от 100 до
  60000 мс). `max_result_chars` — ограничение результата для модели (по умолчанию
  12000, от 100 до 20000 символов). Для медленной модели и веб-поиска начните с
  3000. Действует общий лимит LLM-агента 65 секунд; включённый `local_progress`
  сохраняет беззвучное ожидание, но не отменяет этот предел.
- До восьми серверов подключаются параллельно на время **одного локального
  ответа**. Затем соединения закрываются, stdio-процессы завершаются. Каталог
  обновляется на следующем ответе. Поддерживаются до 128 инструментов вместе со
  встроенными, до восьми страниц каталога и до 256 объявленных инструментов на
  сервер; при превышении лимита настройте фильтры или каталог на стороне MCP.
- Ошибка одного сервера не отключает встроенные инструменты и остальные MCP.
  В журнале видны имя сервера, число инструментов, имя вызова, время и исход;
  адреса с секретами, заголовки, аргументы и результаты туда не записываются.
- В модель передаются текст и `structuredContent`. Бинарные изображения/аудио и
  MCP resources/prompts отдельно не предоставляются. Длинный результат обрезается
  с отметкой `truncated`; ошибка инструмента остаётся ошибкой, а не успехом.
- После чтения приватной истории и в следующих связанных репликах MCP-вызовы
  по умолчанию блокируются вместе с внешним веб-чтением. Для конкретного
  доверенного сервера можно явно задать `allow_private_history: true`; это
  разрешит передавать ему данные из истории. К внешнему поиску такое разрешение
  автоматически не добавляется.

Изменение списка серверов, транспорта, фильтров или авторизации требует
**перезапуска Go-сервера**, но не правки кода и не пересборки. На колонке используйте
`control.sh restart` из установленного пакета YAM; настройки хранятся в постоянном
каталоге состояния и сохраняются при обновлении пакета. `/healthz` показывает
`mcp_servers_configured` — число настроенных серверов; это не проверка их доступности.

## Правила маршрутизации

Правила задаются в объекте **`routing`** основного `config.json` и меняются
без правки Go-кода и пересборки. Полный пример, повторяющий прежнее поведение,
уже находится в [config.example.json](../config.example.json).

Если `routing` отсутствует, используются встроенные значения по умолчанию.
Указанные поля объекта перекрывают defaults; пропущенные поля сохраняются.
Массив **`rules` заменяется целиком**, а не дополняется. Поэтому для добавления
правила с сохранением прежних скопируйте/измените полный массив из примера.
`"rules": []` отключает быстрые правила, оставляя `default_route`.

В режиме `observe` WebSocket всё равно пересылается в Яндекс: маршрутизация
включается в `hybrid`. Для голоса решение принимается после финального ASR
Яндекса; текстовый запрос удерживается до решения. Пустой ASR идёт в облако
без классификации.

### Формат правил

Ниже — фрагмент пользовательского конфига. В нём явный префикс LLM специально
поставлен раньше домашнего правила:

```json
{
  "routing": {
    "rules": [
      {
        "name": "explicit_llm",
        "route": "llm",
        "match": {"starts_with_any": ["спроси нейросеть", "джарвис,"]}
      },
      {
        "name": "home_lights",
        "route": "home",
        "match": {
          "contains_all_groups": [["свет", "ламп"], ["включ", "выключ"]],
          "contains_none": ["песню", "музыку"]
        }
      },
      {
        "name": "cloud_services",
        "route": "yandex",
        "match": {"contains_any": ["погода", "таймер", "будильник"]}
      }
    ],
    "default_route": "classify",
    "classifier": {"timeout_ms": 8000, "on_error": "yandex"},
    "refusal": {"enabled": true}
  }
}
```

Объедините фрагмент с остальными настройками сервера; это не полный config.
У каждого правила нужны уникальное непустое `name`, `route` из
`home` / `llm` / `yandex` и `match`. **Первое совпавшее правило побеждает**:
приоритет определяется только порядком в массиве. `"disabled": true`
пропускает правило при сопоставлении, но не отменяет проверку его синтаксиса.

Все заданные условия `match` соединяются через **И**:

| Поле | Условие |
| --- | --- |
| `contains_any` | В тексте есть хотя бы одна указанная подстрока |
| `contains_all_groups` | Из **каждой** группы есть хотя бы одна подстрока: группы соединяются через И, элементы группы — через ИЛИ |
| `contains_none` | Ни одной из перечисленных подстрок нет |
| `starts_with_any` | Текст начинается хотя бы с одного указанного префикса |
| `regex` | Совпало регулярное выражение Go/RE2 |

Сопоставление по умолчанию не учитывает регистр. Подстроки не являются целыми
словами; пробелы в обычных правилах значимы. Для границ, альтернатив или
необязательных пробелов можно использовать `regex`, например
`"regex": "^объясни\\s+.+"` в JSON. Регулярные выражения компилируются при
загрузке, не на каждом запросе.

Пустые строки, пустые группы и правило без положительного условия запрещены;
одного `contains_none` недостаточно. Для безусловного выбора используйте
`default_route`. Неизвестные поля и маршруты, одинаковые имена и некорректный
regex отклоняются до применения конфига.

### Если ни одно правило не совпало

`default_route` принимает `home`, `llm`, `yandex` или `classify`:

- `home` / `llm` / `yandex` сразу выбирают соответствующий обработчик;
- `classify` вызывает LLM-классификатор для выбора одного из трёх маршрутов.

Параметры `classifier`:

| Поле | По умолчанию | Назначение |
| --- | --- | --- |
| `prompt` | Русская инструкция из полного примера | Системная инструкция классификатору; ожидается JSON `{"route":"home"}`, `{"route":"llm"}` или `{"route":"yandex"}` |
| `timeout_ms` | `8000` | Время классификации, от 1 до 60000 мс |
| `on_error` | `yandex` | `home`, `llm` или `yandex` при ошибке, тайм-ауте, неверном JSON или неизвестном ответе маршрута |

Например, `"default_route": "yandex"` полностью убирает классификацию для
несовпавших запросов. Обычная генерация ответа LLM и планирование HA при этом
сохраняются для правил `llm` и `home`.

### Правила по умолчанию

Без пользовательских изменений используется такой порядок:

| Приоритет | Условие | Маршрут |
| --- | --- | --- |
| 1. `assistant_readonly` | История запросов, чтение URL и страниц | `llm` |
| 2. `home_devices` | Домашнее устройство/показатель и слово действия/состояния, кроме музыкальных маркеров | `home` |
| 3. `complex_queries` | Явный запрос к модели или сложная задача | `llm` |
| 4. `yandex_services` | Погода, музыка, таймер, будильник, время | `yandex` |
| 5. Нет совпадений | LLM-классификатор; при ошибке Яндекс | `classify` |

Домашнее правило содержит группы подстрок вроде `свет`, `ламп`, `люстр`,
`розетк`, `штор`, `кондиционер`, `датчик`, `температур`, `влажност` и
`включ`, `выключ`, `открой`, `закрой`, `установ`, `состояни`, `горит`.
Подстроки `песню`, `песни`, `музыку`, `радио`, `трек` исключают совпадение
этого домашнего правила.

Маркеры сложных задач по умолчанию: `спроси нейросеть`, `спроси свою модель`,
`напиши код`, `напиши программу`, `реши задачу`, `проанализируй`,
`сравни варианты`, `объясни подробно`. Полные списки — в конфиге-примере.

| Фраза | При стандартном порядке |
| --- | --- |
| «Выключи свет в кабинете» | `home` |
| «Напиши код сортировки» | `llm` |
| «Спроси нейросеть про погоду» | `llm` |
| «Спроси нейросеть, включи свет» | `home`; переставьте явное правило LLM выше, если нужно другое поведение |
| «Включи песню про свет» | `yandex` |
| «Сколько будет три плюс четыре?» | Решает классификатор |

Это по-прежнему эвристики: стандартная подстрока «температура» может выбрать
`home` и вне домашнего контекста. Теперь её можно убрать/уточнить в JSON.

### Что выполняют обработчики

Если `QUASAR_HOME_MCP_URL` не задан, выбранный маршрут `home` заменяется на
`yandex` до начала локальной обработки и потокового ожидания. Это относится
ко всем правилам, `default_route`, результату классификатора и его `on_error`.
Примеры с `home` выше предполагают подключённый HA.

- `home`: выбор разрешённых устройств, ограниченный план и проверка результата
  в HA. Распознанные шаблоны вопросов о состоянии, например «горит ли свет»,
  используют отдельную ветку без физических действий.
- `llm`: краткий ответ модели; она не получает произвольный доступ к HA.
- `yandex`: разрешение штатного облачного исполнения. Аудио, неизвестные
  сообщения и обычные ответы проходят исходными байтами; для голоса Go управляет
  служебным approval-флагом и Continue/Cancel.

Ошибку HA нельзя превратить в повтор команды в облаке: действие могло уже
выполниться. Поэтому после начала `home` запрос при ошибке не отправляется
в Яндекс, даже если `classifier.on_error` установлен в `yandex`.
`on_error` относится **только к классификации до выбора обработчика**.
Ошибка генерации LLM также даёт локальное сообщение, без облачного повтора.
Отмена или истечение общего контекста (90 секунд) могут прервать озвучивание.

### Переход к LLM после отказа Алисы

`routing.refusal` задаёт дополнительную проверку уже полученного облачного
ответа, независимо от того, как был выбран маршрут `yandex`:

```json
{
  "routing": {
    "refusal": {
      "enabled": true,
      "prefixes": ["я не знаю", "я не поняла", "увы"],
      "contains_any": ["не знаю", "не поняла", "не могу понять"]
    }
  }
}
```

Нужны оба условия: ответ начинается с одного из `prefixes` **и** содержит
одну из фраз `contains_any`. Регистр и повторные пробелы в этой проверке
нормализуются. `"enabled": false` отключает замену отказов. Полные стандартные
формулировки сохранены в [config.example.json](../config.example.json).

Защита от двойного исполнения не настраивается: замена допустима только до
начала облачного аудио и без исполнительных/неизвестных директив.
`client_action:tts_play_placeholder` допустима. Исходный отказ и его аудио
подавляются, LLM получает исходный вопрос, ответ озвучивается через Яндекс TTS.
Если условия не соблюдены, сохраняется штатный ответ Алисы.

### Проверка и применение изменений без перезапуска

Сначала проверьте JSON и выбранный маршрут, загрузив окружение своей установки:

```sh
set -a
. ./runtime.env
set +a
./bin/quasar-bridge -config config.json -check-config
./bin/quasar-bridge -config config.json -route 'Выключи свет в кабинете'
```

`-check-config` валидирует конфигурацию без сетевых вызовов. `-route` не
управляет устройствами, не генерирует ответ и не выполняет запрос в Яндексе,
но может вызвать LLM-классификатор, если правила не совпали. Пример результата:
`{"route":"home","rule":"home_devices","source":"rule"}`.
Другие значения `source`: `default`, `classifier`, `classifier_error`.
В отличие от него, `-query` выполняет выбранный локальный обработчик.
Диагностические флаги нельзя совмещать.

Для systemd:

```sh
sudo systemctl reload quasar-bridge
sudo journalctl -u quasar-bridge -n 20 --no-pager
```

Обновлённый шаблон unit содержит `ExecReload=/bin/kill -HUP $MAINPID`.
Если unit уже был установлен, добавьте эту строку в его `[Service]` (сохранив
свои пути/пользователя) и выполните `sudo systemctl daemon-reload`.
При ручном запуске отправьте `kill -HUP PROCESS_ID`, заменив `PROCESS_ID`
PID работающего Go-процесса.

Успешная отправка сигнала ещё не доказывает применение: в журнале должно
появиться **`routing_reloaded`**. `/healthz` возвращает `routing_revision`
и число активных правил `routing_rules`. При ошибке появляется
`routing_reload_rejected`, а последняя исправная версия остаётся активной.
Сохранять JSON лучше атомарной заменой файла перед сигналом.

Меняются настройки **`routing`** и **`conversation_log`**. Изменение listener, режима, backend URL,
модели, TLS, ACL или `home_warm_area` при таком reload отклоняется: для них нужен
перезапуск. `runtime.env` также не перечитывается сигналом.
Соединения с колонками не разрываются. Каждый начавшийся выбор маршрута
использует один снимок правил; уже идущая классификация заканчивается по нему,
а следующие выборы и проверки отказов используют новую версию. Начатые действия
не повторяются при reload.

Реализация: [routing.go](../internal/bridge/routing.go),
[engine.go](../internal/bridge/engine.go). Ограничения протокола и проверка
результатов HA сохраняются независимо от пользовательских правил.

## Особенности Home Assistant

Учитываются только сущности с разрешением Assist (`conversation=true`).
Названия областей, friendly name и aliases используются для поиска целей;
состав групп приходит из `member_entity_ids`. Разрешения обнаружения кешируются
на две минуты, перед действием проверяются заново.

План проверяется целиком до исполнения: запрещены неизвестные/недоступные
цели, произвольные сервисы и параметры, дубли и пересечение группы с её
участниками. Максимум четыре действия на запрос. Более 80 кандидатов,
контекст свыше 24 КБ или неполная выдача требуют уточнения/прерывают обработку;
предел обнаружения — 2000 сущностей на домен.

После сервиса читается `ha_get_state`. Для включения/выключения `light`,
`switch`, `fan` проверяется итоговое состояние; для остальных команд
подтверждается только отправка. Список поддержанных сервисов находится в
[`internal/home/controller.go`](../internal/home/controller.go).

LLM может пропустить отдельный светильник при команде для всей комнаты.
Проверка выбранных целей не гарантирует полноту покрытия комнаты. Сверяйте
группы и отдельные устройства. Вопросы о состоянии передают модели указание
не считать настройки Adaptive Lighting источниками света; отдельного
универсального фильтра всех служебных устройств нет.

## Автозапуск на Linux с systemd

Ниже — установка по шаблону для Debian/Ubuntu. Настроенные `config.json`,
`runtime.env` и `private/certs/server.{pem,key}` должны уже существовать.
Бинарник должен быть собран для архитектуры Linux-сервера. Перед
`systemctl enable --now` остановите ручной процесс через Ctrl+C в его терминале.

Если пользователь уже создан, пропустите `useradd`.

```sh
umask 077
sudo useradd --system --user-group --home-dir /opt/quasar-bridge \
  --shell /usr/sbin/nologin quasar-bridge
sudo install -d -m 755 /opt/quasar-bridge
sudo install -d -o root -g quasar-bridge -m 750 /etc/quasar-bridge
sudo install -m 755 bin/quasar-bridge /opt/quasar-bridge/quasar-bridge
```

Для cross-build
в команде `install` используйте имя соответствующего Linux-бинарника.
Удалите или обновите относительные `QUASAR_TLS_CERT`/`QUASAR_TLS_KEY` в `runtime.env`, если
они там заданы: окружение перекрывает абсолютные значения JSON. Относительные
пути считаются от `WorkingDirectory`, а не от расположения `config.json`.
Шаблон unit использует `/opt/quasar-bridge`, `/etc/quasar-bridge` и отдельного
пользователя; при другой установке измените unit или systemd override.


Подготовьте конфиг с абсолютными TLS-путями:

```sh
python3 - <<'PY'
import json
from pathlib import Path

config = json.loads(Path('config.json').read_text())
config['tls_cert'] = '/etc/quasar-bridge/server.pem'
config['tls_key'] = '/etc/quasar-bridge/server.key'
Path('private/config.systemd.json').write_text(json.dumps(config, indent=2) + '\n')
PY
sudo install -o root -g quasar-bridge -m 640 \
  private/config.systemd.json /etc/quasar-bridge/config.json
sudo install -o root -g quasar-bridge -m 640 runtime.env /etc/quasar-bridge/runtime.env
sudo install -o root -g quasar-bridge -m 640 \
  private/certs/server.pem /etc/quasar-bridge/server.pem
sudo install -o root -g quasar-bridge -m 640 \
  private/certs/server.key /etc/quasar-bridge/server.key
sudo install -m 644 scripts/quasar-bridge.service /etc/systemd/system/quasar-bridge.service
sudo systemctl daemon-reload
sudo systemctl enable --now quasar-bridge
sudo systemctl status quasar-bridge --no-pager
```


При реальном пересечении сети контейнеров и адреса LLM проверьте маршрут
командой `ip route get LLM_IP`. Необязательный шаблон
`scripts/quasar-host-route.service.example` берёт назначение, шлюз и интерфейс
из `/etc/quasar-bridge/route.env`; образец — `scripts/route.env.example`.
Основной сервис не включает этот маршрут автоматически.

## Диагностика

```sh
sudo journalctl -u quasar-bridge -n 100 --no-pager
```

| Симптом | Что проверить |
| --- | --- |
| `configuration rejected` | Неизвестные JSON-поля, пару cert/key, формат `allowed_ips`, обязательные настройки `hybrid` и активные env overrides |
| `403 forbidden` от Go | IP клиента в `allowed_ips`, в том числе адрес проверяющей машины |
| TLS error / колонка не подключается | Доверие CA на колонке, SAN и hostname/IP URL, DNS, firewall, порт |
| В журнале нет кадров после речи | Правильность `uniProxyUrl`, QUIC-обход и применение config после перезагрузки |
| `401`/`403` от MCP или неизвестные tools | Полный Secret URL, загруженный `runtime.env`, совместимость набора `ha_*`; OAuth/Bearer для MCP клиент не выполняет |
| `LLM returned HTTP 400` | Точный model ID, базовый URL с `/v1`, поддержку `response_format` и `chat_template_kwargs` вашим API |
| Устройство не находится | Assist exposure, область, friendly name/aliases, состояние `unknown`/`unavailable` |
| Команда прошла частично | Отдельные приборы вне группы, лимит действий, проверка остальных состояний в HA; не повторяйте весь запрос вслепую |
| Долгий ответ | Скорость LLM, классификация, HA и первоначальный обход разрешений; `home_warm_area` сокращает холодное обнаружение |

Маршрут виден в `native_route` (`home`, `llm`, `yandex`), замена отказа —
в `native_fallback`, готовый аудиопоток — в `native_tts_ready`.
`home_warm ready=true` означает завершение подготовки кеша, не действие.
Сервер не записывает тексты запросов, аудио и токены в штатный журнал.

В пилоте ответы HA занимали примерно 10–17 секунд. Внешний клиент может
получить тайм-аут раньше завершения и озвучивания. Это не доказывает, что
физическое действие не произошло: сначала проверьте состояние, затем решайте,
нужен ли повтор. Подробности проверок — [docs/validation.md](../docs/validation.md).

## Откат

Для быстрого отключения локальной маршрутизации задайте `mode: "observe"`
(либо `QUASAR_MODE=observe`, если используете env override) и перезапустите
Go-сервер. Колонка продолжит работать через него с Яндексом.

Для полного отката сначала восстановите штатную конфигурацию и CA на колонке:

```sh
ssh -p "$SPEAKER_SSH_PORT" "root@$SPEAKER_HOST" \
  "sh '$STAGE/rollback-pilot.sh' && reboot"
```

Убедитесь, что колонка снова подключается штатно. После этого можно остановить
и отключить прокси:

```sh
sudo systemctl disable --now quasar-bridge
```

При нестандартных firmware-путях используйте те же `QUASAR_DEVICE_*`, что при
применении. Если был установлен отдельный host-route unit, его отключение и
удаление конкретного маршрута выполняются отдельно по вашей конфигурации.

## Справочник конфигурации

Переменные окружения имеют приоритет над JSON, в том числе если значение
пустое. Пустые `listen`, `upstream` и `mode` затем получают значения
по умолчанию. JSON-файл всё равно должен существовать. Неизвестные поля отклоняются.

| JSON | Переменная окружения | Значение/назначение |
| --- | --- | --- |
| `listen` | `QUASAR_LISTEN` | Адрес и порт; по умолчанию `localhost:8443` |
| `upstream` | `QUASAR_UPSTREAM` | По умолчанию `wss://uniproxy.alice.yandex.net/uni.ws` |
| `mode` | `QUASAR_MODE` | `observe` по умолчанию, либо `hybrid` |
| `tls_cert` | `QUASAR_TLS_CERT` | Путь к сертификату сервера |
| `tls_key` | `QUASAR_TLS_KEY` | Путь к ключу; задаётся вместе с сертификатом |
| `allowed_ips` | `QUASAR_ALLOWED_IPS` | JSON-массив или список IP через запятую; пустой отключает фильтр |
| `llm_base_url` | `QUASAR_LLM_BASE_URL` | Базовый API URL с `/v1` |
| `llm_model` | `QUASAR_LLM_MODEL` | Идентификатор модели |
| `home_warm_area` | `QUASAR_HOME_WARM_AREA` | Подготовка кеша света/выключателей области, не область по умолчанию |
| `dialogue_context` | — | Короткая память локального диалога; по умолчанию включена, требуется перезапуск |
| `local_progress` | — | Потоковое ожидание долгих локальных ответов; по умолчанию выключено, требуется перезапуск |
| `assistant_tools` | — | Инструменты диалоговой LLM, лимиты и часовой пояс; требуется перезапуск |
| `conversation_log` | — | Настройки JSONL-журнала; перечитывается по `SIGHUP`, по умолчанию выключен |
| `routing` | — | Правила, классификатор и детектор отказов; перечитывается по `SIGHUP` |
| — | `QUASAR_HOME_MCP_URL` | Необязательный URL HA MCP; пустой отключает HA и передаёт домашние запросы в Яндекс |
| — | `QUASAR_LLM_API_KEY` | Необязательный Bearer-ключ LLM |

Если оба TLS-поля пусты, сервер работает по HTTP/WS. Примеры подключения
колонки на отдельный хост выше предполагают TLS; для них нужен именно WSS endpoint и доверие CA.
