# OpenRouter: отдельный классификатор и резерв для ChatGPT

Необязательный блок `openrouter` оставляет ChatGPT основным провайдером ответов,
отправляет нейросетевую классификацию в Jev и повторяет неудачный запрос через
OpenRouter при явном исчерпании квоты ChatGPT.

```json
{
  "llm_api": "chatgpt",
  "openrouter": {
    "enabled": true,
    "classifier_model": "~typesafe/jev-latest",
    "fallback_model": "openai/gpt-6.1-terra"
  }
}
```

Это фрагмент существующей конфигурации. Выберите доступную вам резервную модель.
Настройки reasoning, максимального ответа и hosted tools берутся из основных
`llm_*` параметров. По умолчанию интеграция выключена; в этой версии она требует
ChatGPT как основной API и Jev latest как классификатор.

Передайте ключ только через `QUASAR_OPENROUTER_API_KEY` в окружении сервиса.
Не помещайте его в JSON и не публикуйте в отчётах. Для systemd можно использовать
отдельный защищённый EnvironmentFile. После настройки перезапустите сервис.
`-check-backends` проверяет основной ответ, классификатор и резерв; проверка
резерва обращается к платному API и может расходовать баланс.

Jev использует OpenRouter Decisions `/api/alpha/decisions`, а не chat completions.
Варианты ответа — `yandex`, `llm`, `home`; назначение определяется существующим
промптом маршрутизации. Передаются распознанный текст и текущий контекст, без аудио.
Правила и продолжения диалога работают до классификатора как прежде. Ошибки Jev
обрабатываются через существующий `classifier.on_error`; порога confidence нет.

Резерв вызывается только для явных кодов исчерпания квоты:
`subscription_sharing_usage_limit_exceeded`, `insufficient_quota` и
`credit_balance_exhausted`. Обычный HTTP 429, rate limit, ошибки авторизации,
сети или сервера не включают платный резерв. Следующий inference round снова
начинается с ChatGPT; постоянного переключения нет.

Повторяется только неудачный inference round. Уже выполненные инструменты
передаются как результаты. OAuth-токены не передаются OpenRouter; специфичные
для другого провайдера Responses items преобразуются в обычные сообщения
и вызовы инструментов. Контекст отмены и общий срок запроса сохраняются.
Встроенный поиск отображается в `openrouter:web_search`; запрет hosted tools
после чтения приватной истории сохраняется.

Проверки с HTTP/SSE fixtures покрывают коды квоты, условия без переключения,
ключи разных провайдеров, результаты инструментов, отмену и срок запроса.
Авторизация и запросы к обоим провайдерам проверены на работающем Bridge.
Реальная квота для проверки намеренно не исчерпывалась.
